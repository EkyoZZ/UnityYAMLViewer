# 1.3.9

已于北京时间 2026-11-27 15:22:42 正式发布。Windows x64 附件采用画中画掉帧修复后的实测构建，已核对远端大小和 SHA-256。用户确认双音源画中画流畅、开销低、预览无可感延迟且拍手音画同步，也已验证路径选取、锚点框选和两个分层快捷键。[发布说明](../releases/1.3.9.md)

## 开发与验证记录

- Image／绘 Tile 的路径选择按子路径命中，拖动轮廓内、边缘或锚点会平移这一形状。直接选择支持单击和矩形框选锚点，Shift 加选，选中点实心、未选点空心。拖动部分锚点或贝塞尔手柄时，只有受影响的参数形状需确认转换；整个子路径平移保留矩形参数。参考 PhotoCraft 提交 `85e8ff5399793d66a87898332653eab61e918d24` 的路径组件与直接选择工具。
- 在同层多个形状中用路径选择明确选中一个，Ctrl+J 将它原位复制到新矢量层，Ctrl+Shift+J 将它剪切到新矢量层并从原层移除。一次撤销恢复整个操作。剩下一个形状时保留该形状类型；剪出布尔组件后，独立形状显示自身轮廓，剩余同色组的首个形状作为填充基础。
- 2026-11-27 用户实测通过四项画布操作：用路径选择移动单条子路径、用直接选择框选锚点、用 Ctrl+J 复制选中形状到新层并保留原形状、用 Ctrl+Shift+J 剪切选中形状到新层并从原层移除。
- 合并形状层保存 PSD 时按子路径索引读写受支持的原生矩形参数，包括尺寸、四角半径与旋转。混合普通路径和矩形的图层逐项处理。旧 PSD 缺少矩形参数、参数已失效或变换不受支持时沿用已有贝塞尔路径。路径交互、分层撤销及 PSD 往返用例已通过 `cargo check --locked --offline --tests` 编译检查。分层撤销、Photoshop 往返和关于窗口展示待实机验证。
- 修复 Photoshop 保存的同层多矩形 PSD 因 `vowv` 版本块退回合成图的问题。识别样本中的版本 2 标记，通过 `vsms` 保留两条可编辑轮廓。已核对真实样本中的两个合并子路径，编译检查通过，应用重开待验证。
- 矢量形状的填充色从形状工具栏或图层缩略图即时修改。新建形状默认取当前前景色，在未选中矢量图层时可指定独立的新建填充或恢复使用前景色。已创建的形状保留自己的填充。图层缩略图不显示「填充」悬浮提示。修复在缩略图色板里选色时，图层列表尚在绘制就清空缩略图缓存所导致的闪退（用户已实测通过）。复合矢量层的锚点选取工具可选择和拖动单个子路径的锚点。路径 / 直接选择工具栏可选择子路径、编辑宽高和锁定比例，并修改后续子路径的布尔操作；填充色继续作用于整层。界面待验证。新形状加入已有层时采用该层的填充色，合并受支持的矢量图层时统一使用最上层的填充色。已有异色复合形状仍按组写入 PSD。编译检查通过，界面及关于窗口待验证。
- 铅笔和画笔工具栏的绘制颜色即时更新前景色。绘制区的前景色和背景色色板也即时应用，关闭色板后保留选取的颜色。其他色板仍需确认。编译检查通过，界面及关于窗口待验证。

- 选区工具栏提供铅笔／画笔切换。铅笔按选区硬边填充，画笔在选区内侧建立一像素的柔和过渡。工具栏与颜色填充快捷键共用选择，整层填充与删除选区保持原有行为。编译检查通过，界面待验证。

- 拖绘框画、矩形／椭圆选区和矢量图形时按 Shift，可画正方形、正圆、等边三角形和正多边形。菱形 Tile 上的框画和矩形选区保留菱形方向，两条对角线等长。选区的 Shift 追加规则继续生效。编译检查通过，界面待验证。

- Image 和绘 Tile 的形状工具加入「新建图层／合并形状」。合并形状可把新画的形状加入当前可编辑的矢量图层；合并普通矢量形状图层时保留形状和堆叠顺序，填充色采用最上层，可在图层属性中按形状编辑，整层支持移动和变换。带蒙版、特殊混合或图层效果等的合并沿用像素合成，可绘制合并、减去、相交和排除的子路径。同色复合形状以原生多子路径形状层写入 PSD；异色复合形状以单组内连续同色的形状层写入，保留叠放顺序。暂不支持 Photoshop 的开放路径、子路径连接和复合矢量蒙版，以及永久合并形状组件。编译检查和 PSD 回归测试通过。Photoshop 2024（25.3.1）已打开同色、异色两个样例，移动可编辑形状层、另存并重开，确认编辑位置与图层结构保留。核对另存文件的路径记录，合并、减去、相交、排除四种操作均保留。关于窗口展示待验证。
- Windows 录屏历史的每条记录右侧显示本地创建日期和时间。现有记录从录屏文件名读取时间，文件已移除但仍在历史中时也可显示。编译检查通过，界面待验证。
- 录屏设置新增默认关闭的录制诊断。开启后正常输出混音成片，并在同目录的 diagnostics 文件夹保存启用的混音前系统声和麦克风 WAV（含预热），以及桌面、摄像头和两路音频的 FFmpeg 输入包时间戳。USB 双音源拍手诊断通过。同一诊断样本两次拍手均见于麦克风 WAV（5.301／10.216 秒）和混音（5.237／10.152 秒），系统声音 WAV 静音。按接触画面估算，声分别慢约 3.6 秒，相隔约 5 秒的两次偏差相近。日志显示放行前画中画预览持续消费视频，音频输入长期未被拉取，混音首批样本独立归零后保留了音频积压。此前的 700 毫秒样本没有原始轨，不能复原其具体时间线。
- 根据拍手诊断修复倒计时期间混音支路积压。两路音频在预热期间就持续消费，成片音画按同一个系统时钟时刻放行；新双音源拍手样本中，成片音频峰值在 2.822／7.658 秒，手掌约在 6.155／10.988 秒首次接触，画面两次都滞后约 3.33 秒。原始麦克风有两次拍手（6.299／11.135 秒），去掉预热后间隔与混音一致。日志在放行前只读到 2 个桌面包，而摄像头已读到 107 帧；需继续排查桌面与摄像头合成的预热进度和时钟。用户观察到实时预览也有明显延迟。
- 画中画预热时持续消费桌面和摄像头帧，两路在进入合成前按共同时间基准标记帧，成片视频丢弃早于倒计时结束的合成帧。编译检查通过，USB 双音源拍手及长录制的流畅度待验证。
- 2026-11-27 继续排查画中画 CPU 开销。USB 双音源样本使用 NVENC，11.4 秒仅录得 17 帧。按诊断日志的读取时间，从放行到用户点击停止，桌面输入 18 包、摄像头视频输入 351 包；日志没有当时的 CPU 计时，无法据此判定掉帧根因或拍手偏差。
- 画中画的桌面和摄像头预热支路每帧只取一个像素；仅屏幕录制也用一个像素通知首帧就绪。画中画优先探测 NVENC 能否直接接受合成画面的 YUV420P，保留 NV12、QSV 和软件编码回退。最多 1080p 像素、30 FPS 的硬件编码画中画使用至多四个合成滤镜线程。启用录制诊断后，`timestamps.log` 记录 FFmpeg 的进程 CPU 时间和经过时间。
- 2026-11-27 CPU 优化版实录（`recording-1795757613044012900.mp4`）约 11 秒只有 16 帧，视频平均 1.46 FPS，最长帧间隔 2.30 秒。倒计时可见的 2.98 秒读到 89 个桌面包和 88 个摄像头包，放行至停止的 12.73 秒只读到 17 个桌面包，摄像头仍有 377 个。FFmpeg 在 15.89 秒内使用 3.20 秒进程 CPU 时间。单次样本没有 G HUB 开关对照。
- 调整画中画的 FFmpeg 调度。桌面和摄像头各用独立滤镜图读取，画面合成与音频处理也分别调度。启用诊断时，两条混音前 WAV 直接使用跟视频共用时钟的预热音频，保留原始采样和倒计时。画中画 NVENC 显式设置零帧输出延迟，避免起录时等待编码器攒帧。

- 2026-11-27 用户确认双音源画中画实录流畅、CPU 开销低，拍手音画同步，实时预览无可感延迟。本次 1080p30 NVENC 成片 `recording-1795762645780455800.mp4` 的视频轨为 9.575 秒、261 帧，平均 27.26 FPS。按显示时间戳，开头两帧相隔 142 毫秒，之后 236 个间隔约为 33 毫秒、23 个约为 67 毫秒。修复前样本最长间隔为 2.30 秒。本次 FFmpeg 在 12.748 秒内消耗 4.594 秒进程 CPU 时间，折合本机 16 个逻辑处理器总容量的约 2.25%。预览延迟和拍手同步由用户观察确认。

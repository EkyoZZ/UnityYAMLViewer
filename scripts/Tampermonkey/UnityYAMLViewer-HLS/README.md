# UnityYAMLViewer · HLS 嗅探助手

原始“威软FFmpeg · HLS流嗅探器”保留在相邻目录，本目录为独立改造版，不覆盖原脚本。

## 安装与使用

1. 最低需要 Windows 版 UnityYAMLViewer v1.3.4；使用 v1.3.4 或更高版本，正常启动一次，以注册当前用户的 `unityyamlviewer:` 协议。移动程序位置后重新启动一次更新路径。
2. 在软件“第三方支持 → 网页浏览器HLS嗅探助手”依次点击“安装油猴插件”和“安装脚本”，分别从 [Tampermonkey 官网](https://www.tampermonkey.net/) 安装浏览器插件、从 [Greasy Fork](https://greasyfork.org/zh-CN/scripts/604041-unityyamlviewer-hls-%E5%97%85%E6%8E%A2%E5%8A%A9%E6%89%8B) 安装助手；也可在 Tampermonkey 新建脚本，粘贴本目录 `UnityYAMLViewer-HLS.user.js` 的完整内容并保存。建议关闭功能重叠的旧嗅探脚本，避免重复面板或重复请求包装。
3. 打开 HTTP/HTTPS 网页并播放视频。面板默认折叠，仅显示“▶ HLS 数量”，展开及折叠背景均为 30% 不透明度、文字和按钮保持清晰。展开标题栏显示 HLS 数量及绿色“在 UnityYamlViewer 中解析”按钮，标题不显示品牌前缀；该按钮发送当前网页 URL，由软件自行分析，即使未发现 HLS 也能使用。点击标题空白/数量可折叠，拖动标题栏可移动（按钮区域不触发拖动），位置限于可视窗口内，窗口缩小或展开时自动校正边界；仅保留当前页面位置，不跨页面保存。
4. 每个候选地址依次提供“复制链接”“在工具中打开”“在 UnityYamlViewer 中打开”。“在工具中打开”保留原在线 FFmpeg 工具入口，将所选地址作为参数交给该工具；原“直接下载 TS”操作由唤起 UnityYAMLViewer 替代。浏览器可能提示允许打开外部应用；脚本只能发出请求，不能确认软件已经成功播放。
5. 请求本地打开后，面板显示默认收起的“▶ 没有打开？”；点击才展开最低版本 v1.3.4 说明、“下载 UnityYAMLViewer”和“重新打开”，再次点击可收起，每次请求本地打开恢复收起。下载入口在新标签页打开项目 GitHub Releases，下载 Windows 版 v1.3.4 或更高版本，解压并运行一次后，回到原网页重试最近一次选择的媒体或网页地址。脚本无法可靠判断软件是否安装或唤起成功，不会自动跳转下载页。

协议格式为 `unityyamlviewer://open?url=<encodeURIComponent(媒体地址)>&referer=<encodeURIComponent(来源页)>`。软件只还原外层参数一次，媒体地址内部的百分号编码保留；HLS 走直接播放，其他 HTTP/HTTPS 地址沿用打开 URL 流程。已运行时转交当前实例并唤醒窗口，未运行时启动软件。

## 范围与限制

- 展开宽度按三个操作按钮的实际宽度、间距、内边距与滚动条计算，长地址截断、提示文字换行，不撑宽面板；屏幕不足时按钮允许换行。折叠态仍仅占箭头和 HLS 数量的宽度。
- 扫描已有 video/source 元素及网页源码中的绝对 m3u8 地址，并在脚本所在页面环境监听 fetch/XHR 的 HLS 请求和响应类型。候选按完整地址去重，上限 300 条；源码最多扫描前 3,000,000 个字符。
- 脚本提供复制、手动打开原在线工具或唤起本地软件，不直接下载、解密视频，不向软件传递 Cookie 或浏览器凭据。本地唤起仅传递媒体 URL 与来源页 Referer；在线工具功能由第三方页面提供。
- 跨域 iframe、Worker、Service Worker、浏览器原生播放请求、页面更早保存的请求函数、脚本管理器隔离环境等可能导致漏检；不承诺发现全部媒体。
- 登录、短时签名、DRM、需要额外请求头或 Cookie 的地址仍可能无法在软件播放。过长协议链接（超过 32,000 字符）应复制后在软件中打开；浏览器或系统可能有更低限制。
- 当前只实现 Windows 协议注册；其他操作系统未配置协议关联。无视频的网站不会因此获得额外媒体权限。
- 改造版不继承第三方更新地址，不会被原脚本在线更新覆盖。源码灵感与署名注明在脚本内，许可沿用 MIT。

用户已确认本次安装入口及此前嗅探功能测试通过；具体范围与其他待验证项见工程当前版本记录。
